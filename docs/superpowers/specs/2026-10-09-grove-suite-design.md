# Grove 扩展套件设计规格

- 日期：2026-10-09
- 作者署名：Fern
- 状态：Fern 已确认设计与实施方向（尚未进入实现）
- 适用平台：HanaAgent v2 App（`manifestVersion: 2`），依据仓库内 `docs/APPS.md`

## 1. 目标

为 Fern 的 HanaAgent 个人工作台做一套可持续生长的扩展套件，名为 **Grove**（中文名「林间」）。套件由一个统一管理面板和若干小功能模块组成，功能方向横跨对 Hana 基础能力的扩展（会话统计、Token 统计）与个人事务管理等，之后由 Fern 逐步补充。

**首版只交付管理面板与模块框架**，具体模块先以“规划中”占位，不制造假功能。

## 2. 已确认的约束

1. Hana 只认以 `manifest.json` 为身份的 App，因此套件的 Hana 侧身份为**一个宿主 App**，内含多个模块。
2. 模块边界按“可独立抽取”设计：同一份模块核心可构建成两种安装产物（见第 6 节）。
3. 归属在**安装时**决定，安装后固定；不支持运行时在两种形态之间切换，也不尝试自动接管。
4. 面板版的模块随面板包一并交付；新增模块通过更新面板包加入，**不在运行时下载或执行外部模块代码**。
5. 界面只管理 Grove 自己的模块，**不展示、安装或管理** Hana 市场中的 App、Skill、Recipe、Connector、Role、Bundle 等其他扩展类型。
6. 旧 Grove 的源码、打包产物与旧套件约定文档已清理，本设计不继承其架构。

## 3. 平台事实与边界

以下均来自仓库内 `docs/APPS.md`，实现时以平台文档为准。

| 事实 | 对设计的影响 |
| --- | --- |
| App 的身份、权限和生命周期绑定在自己的 manifest 与入口上；注册随 App 回收 | 面板内模块不具备独立 App 身份 |
| 没有公开接口让一个 App 枚举、接管或去重另一个已安装 App；`hidden: true` 只影响列表展示 | 不承诺“面板存在就自动并入独立模块”；不做双装去重 |
| `sdk.tools.register` 等注册方法返回回执，可 `disposeAsync()` 撤销 | 模块用动态注册表达启停 |
| `contributes.ui`、`homeActions`、`cards` 等是清单级静态贡献，属于宿主 App | 模块开关不能让静态入口随之消失，故首版模块入口以动态注册为主 |
| 能力声明属于 App，权限由用户在 Hana 设置中授予；撤销需用户操作 | 面板版声明所含模块所需能力的并集；模块开关不授予也不撤销权限 |
| 安装目录对 App 只读；可写区是 `{HANA_HOME}/app-data/{appId}`（`dataDir`），`storage` 单作用域 16 MiB 硬上限 | 模块数据按模块 ID 分区存放；大数据用 `dataDir` |
| `hana.theme` 提供宿主签发的 `cssUrl` 与可选 `appearance`/`palettes` | 界面样式跟随宿主主题 |
| **Hana v2 没有公开的宿主语言读取接口** | 见第 9 节：语言无法保证跟随 Hana 设置 |
| `sdk.environments` 是隔离环境，不是正式安装入口 | Grove 不安装、管理 Hana 市场扩展 |

## 4. 架构

### 4.1 宿主与模块

- 宿主 App 拥有唯一的 Hana 清单、入口、启动与回收逻辑，以及唯一的常驻套件入口。
- 每个模块有独立目录、稳定的模块 ID、元数据、后端入口和可选界面。
- 宿主维护一份**显式模块注册表**，逐项导入；不扫描目录、不加载未登记代码。构建检查要求模块 ID 不重复、工具与命令名不冲突、宿主清单已声明全部成员模块所需能力。

### 4.2 模块契约

模块元数据至少包含：稳定 `id`、显示名称（可本地化）、用途说明、模块版本、所需 Hana 能力、数据 `schemaVersion`。

模块核心**不直接依赖 Hana SDK**，也不访问其他模块内部实现。宿主向模块提供受限的 `ModuleApi`，覆盖：动态工具、命令、事件订阅的注册；按模块 ID 命名空间的存储读写；日志。模块激活时返回清理句柄；停用时宿主调用句柄并撤销该模块的全部注册。

工具与命令名使用稳定的“套件前缀 + 模块 ID”命名空间；具体命名规则在实现第一步确定并写入构建检查。

### 4.3 适配层

同一份模块核心配两层薄适配：

- **面板适配层**：接入管理面板与宿主能力，由宿主按用户选择启停。
- **独立 App 适配层**：把单个模块包装成标准 v2 App（自有 manifest、图标、权限声明、入口）。

## 5. 模块生命周期与故障隔离

- 记录两类状态：**用户选择**（启用/关闭）与**运行状态**（未启用、启动中、已启用、权限不足、启动失败、停止中）。
- 初次安装面板时所有模块默认关闭；面板更新加入的新模块也默认关闭，不替用户做选择。
- 启用：保存选择→启动模块→注册其工具、命令、订阅。停用：停止接收新操作→取消订阅→撤销注册；设置与数据保留。
- 宿主重启或重载后，按保存的选择重新启动已启用模块。
- 启动失败：回滚已成功的注册，保留用户的启用意图，标记失败并提供重试或停用；不影响其他模块与面板本身。
- 同一模块的启停操作串行化并保持幂等；快速重复点击不得造成重复注册或残留订阅。
- 缺少 Hana 授权时显示“权限不足”并引导用户到 Hana 应用权限设置；面板不绕过授权闸门，也不代为弹出授权。运行中的调用仍由 Hana 逐次校验。
- 启停首版按**套件全局**生效，不按 Agent 区分。

## 6. 数据与安装形态

### 6.1 数据

- 设置与业务数据按稳定模块 ID 分区；停用、重载、更新面板都不删除模块数据。
- 数据携带 `schemaVersion`；格式变化由模块自带迁移处理，迁移失败须保留旧数据并显示错误，不得静默重置。
- 分区是套件内部的逻辑隔离，**不是**强安全沙箱：面板内模块共用宿主 App 的进程、权限与数据目录。

### 6.2 两种安装产物

| 产物 | 说明 |
| --- | --- |
| **面板宿主 App 包** | 内含该版本的全部模块；Hana 中只出现这一个 App |
| **单模块 v2 App 包** | 某模块单独打包，经 Hana 扩展入口导入，拥有自己的 App 身份、权限与数据 |

- 归属由用户导入哪种包决定。**建议同一模块只装一种形态**；若用户刻意同装，套件不承诺自动合并或抑制重复功能。
- 从面板版转为独立版（或反向）时，通过带 `schemaVersion` 的**显式导出/导入**迁移数据，不假设两个 App 的存储互通，也不沿用面板的授权。
- 面板版新增模块权限时，按 Hana 对宿主 App 的权限扩张审查流程处理。

## 7. 管理面板

### 7.1 入口

Hana 中只有**一个常驻的套件入口**，属于面板宿主。拟用 Hana 已公开的整页导航卡承载（须带真实封面与应用图标）；具体清单写法在实现时按平台校验器确认。

### 7.2 页面结构

- 单页纵向布局，**不设左侧分类栏，不设“模块／关于”页签**。
- 标题栏：品牌名 Grove、署名 Fern，右上角“⋯”菜单提供“关于 Grove”（版本、作者、套件简介）与语言偏好。
- 模块按状态纵向分组：已启用、可启用、需处理、规划中；组内**每行两张卡片**，窄宽度自动变单列。
- 首版只有“规划中”一组。

### 7.3 卡片（选定样式：轻叙述卡）

- 内容：意象名、一句贴近日常的功能说明、当前状态、详情入口。
- 卡片主体打开同一面板内的详情页，详情页提供返回入口；启停控件与卡片主体分开，防止误触。
- 规划中的卡片只读：无开关，不打开空白详情，不显示为运行失败。

## 8. 视觉与命名

- 整体延续 Hana 扩展市场的气质：浅暖底、细分隔线、紧凑列表、克制的蓝色交互色；个性化主要体现在**模块命名**，不铺满主题装饰。
- 颜色与组件样式订阅 `hana.theme` 并使用宿主签发的样式，用宿主 CSS 变量起步，不另造重皮肤；明暗主题随宿主。
- 模块采用**意象化名称**。首版示例对应关系（Fern 已认可，仅作展示映射，后续可调）：

| 示例意象名 | 对应方向 |
| --- | --- |
| 向日葵 | 会话统计 |
| 小苔藓 | Token 统计 |
| 松鼠 | 事务管理 |

  意象名只是展示映射，模块 ID 保持稳定，改名不影响数据与注册。
- 图标使用统一风格的轻量线性图形，不用 Emoji；设计稿里的字符仅为占位。

## 9. 多语言

- 词条覆盖简体中文、繁体中文、英语、日语、韩语，前后端共用同一份词典。
- **已知平台缺口**：Hana v2 没有公开的宿主语言读取接口，因此无法保证界面语言与 Hana 手动设置一致。首版按浏览器语言选择，并在“⋯”菜单提供手动覆盖；宿主开放接口后改为优先跟随。
- 品牌名 Grove 保持原名，中文名「林间」；各语言的模块展示名由 Fern 审定。

## 10. 首版范围

- 交付：面板宿主 App、模块注册表与生命周期引擎、`ModuleApi`、状态存储、模块目录页（含“规划中”占位卡）、“关于”入口、主题与多语言接入。
- 不交付：任何真实业务模块、Hana 市场扩展的展示或安装、模块运行时下载、双装去重、运行时形态切换、按 Agent 的启停。
- 占位项是目录数据，不是代码模块：不注册任何工具，不占用入口。

## 11. 验收

1. Hana 中只出现面板宿主的一个套件入口；占位模块标注“规划中”，不可启动，也不可打开空白详情。
2. 启停选择可持久保存；后加入的模块默认关闭。
3. 模块启动失败时保留用户选择并展示错误；其他模块与面板仍可用。
4. 模块动态注册在启用/停用时创建、回收；重复启停与并发点击无重复注册、无残留订阅。
5. 面板包与独立模块包分别通过 Hana 官方 v2 静态校验与隔离启动检查；模块 ID 或工具名冲突、能力声明遗漏会使构建检查失败。
6. 界面颜色随 Hana 明暗主题变化；语言按规则选择并可手动覆盖。
7. 首版无真实业务模块，业务功能不属于验收项；之后每加入一个真实模块，补对应功能测试与 Hana 权限审查验证。

由于首版没有真实模块，启停与故障流程用测试用模块（仅存在于测试中）验证，不用空壳功能冒充可用模块。

## 12. 待定项（实现第一步确定）

1. 宿主 App ID 与目录名、单模块 App ID 的命名规则、套件工具/命令名前缀。
2. 各语言的模块展示名与功能文案（含繁体、日、韩）。
3. 模块图标的具体图形与 App 封面素材。
4. 整页导航卡的清单细节与 `minAppVersion`（取决于实际用到的接口）。
5. 发布前在目标市场检索 App ID 是否被占用。

## 13. 风险

- **语言不一致**：浏览器语言可能与 Hana 手动设置不同；已用手动覆盖缓解。
- **权限并集偏宽**：面板版声明所有成员模块所需能力，用户一次审批覆盖面更大；模块增多后需持续审视，必要时拆为独立 App。
- **双装重复**：平台无去重机制；靠文档建议与命名空间降低冲突概率。
- **Hana 接口演进**：v2 接口仍在变化，实现前以最新平台文档与校验器为准。
